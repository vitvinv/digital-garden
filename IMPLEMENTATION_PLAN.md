# Digital Garden — Implementation Plan

## Architecture (current)

The garden is an **8th Wall Studio AR project** deployed to GitHub Pages at
`garden.v-e-v.org`. Plants are generated by the **PlantStudio** engine
(a pure-Python port of the PlantStudio meristem growth simulator) and grow
one day per day, automatically, in the cloud.

**Per-plant model** (source of truth = plant JSON, not the GLB):

- Each plant is one JSON config: `{plant_id, species, seed, planted_date}`.
- One derived GLB per plant: `digital-garden-AR/src/assets/plants/{plant_id}.glb`.
- Plants are **arranged in the Studio editor** (`.expanse.json`): positions,
  rotations and scales live in the scene, not in the generator.
- Age is `day = today − planted_date`. It never regresses (a stale config
  push can't roll growth back) and catches up automatically if a run is missed.
- The Blender addon stays the design/preview tool (63 species, growth slider
  = `Age (days)`); an "Export Plant Config" operator writes the JSON.

## Conventions

- **GLB naming:** `{plant_id}.glb` — one file per plant (not composite gardens).
- **Plant config path:** `digital-garden-AR/src/assets/plants/{plant_id}.json`
- **Determinism:** `grow_species(species, day, seed)` reproduces byte-identical
  meshes (Park-Miller RNG). Same JSON + same `--day` → byte-identical GLB.
- **Headless output matches Blender export:** `MeshTurtle` scale `0.001`
  (mm→m), `orient_vertices()` (PlantStudio +X → Blender Z-up), then Z-up→Y-up
  glTF conversion; per-face colors baked into exploded vertex colors (COLOR_0).
- **Draco compression:** via `gltf-transform draco` CLI in CI (optional locally).
- **LFS:** `*.glb` under `src/assets/**` is Git LFS; `plants/*.json` is plain text.

## CI workflow

**Deploy (`deploy.yml`)** — on every push to `main` / manual dispatch:
```
checkout (LFS) → npm ci → pip install numpy trimesh → npm i -g @gltf-transform/cli
→ python scripts/plant_glb.py        # regenerates ALL plant GLBs at today's day
→ npm run build (webpack) → upload dist → deploy-pages
```
Every deploy therefore ships current-day GLBs — stale local GLB files can never
leak to the live site.

**Daily growth (`grow.yml`)** — cron `0 6 * * *` / manual dispatch:
```
checkout (LFS) → pip install → gltf-transform → python scripts/plant_glb.py
→ bash scripts/publish.sh           # commit changed plant GLBs, push
→ gh workflow run "Deploy to GitHub Pages"   # GITHUB_TOKEN pushes don't trigger workflows
```
Keeps the repo (and a git-pulled Studio copy) in sync with the latest growth.
