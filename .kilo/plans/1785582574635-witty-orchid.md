# Blender PlantStudio Addon — Implementation Plan

## Vision

Rebuild PlantStudio (1997, Kurtz-Fernhout Software, GPL v3) as a **Blender addon**:
a Python addon that ports PlantStudio's biomass-driven meristem growth simulation,
parses its `.pla` species files (63 species) and `.tdo` 3D object library (57 objects),
and produces **real mesh objects** in a Blender scene — enabling what PlantStudio
never could: **multiple plants composed into one garden scene**, then exported
to GLB into the existing `digital-garden` AR pipeline.

The PlantStudio authors explicitly wished for this: *"We would also love to see it
as, say, a Blender plugin"* and *"Composition of plants done in other tools (like
Blender)"*.

## Source material (in `examples/PlantStudio-master/`)

| Path | Role |
|------|------|
| `for-olpc-python/*.pla` | 9 species libraries, 63 species total (maiden grass, garden flowers, wildflowers, shrubs, grassy plants...) — each a complete parameter set incl. embedded 3D objects + random seed |
| `for-olpc-python/3D object library.tdo` | 57 leaf/petal/bud/seed objects (text: `Point=` + `Triangle=`) |
| `for-olpc-python/umerist.py`, `uplant.py`, `uintern.py`, `uleaf.py`, `uinflor.py`, `ufruit.py`, `uturtle.py`, `u3dsupport.py`, `u3dexport.py`, `urandom.py`, `umath.py`, `utravers.py`, `updcom.py`, `ufiler.py`, `utdo.py` | The algorithm reference (Python 2, GUI-coupled — port the *logic*, not the code) |
| `converted_source/used/*.pas.py` | Same files, earlier translation stage |
| `for-jython/` | Swing-based GUI variant (same core) |

**Porting principle:** the OLPC Python is Python-2 with Delphi compat wrappers
(`conversion_common`, `delphi_compatability`, `except Exception, e:`). We write
**clean Python 3** implementing the same algorithm, using the source as the
algorithmic reference. The `.pla`/`.tdo` resources are used **as-is** (parsed).

## Locked decisions (user-approved)

1. **Python addon producing real mesh objects** (not Geometry Nodes). Geometry
   Nodes may be used later for display only, never for simulation.
2. **Full biomass simulation**: `nextDay()` per meristem — photosynthate
   accumulation, phytomer creation thresholds, probabilistic branching,
   flowering at maturity. Faithful port.
3. **Blender exports into the existing pipeline**: export garden → GLB →
   `digital-garden-AR/src/assets/gardens/{garden-slug}.glb` (same path the AR
   scene reads; publish/deploy workflow untouched).
4. **Deterministic seed control**: UI exposes the seed
   (`kGeneralStartingSeedForRandomNumberGenerator`); same seed + params + day =
   identical plant. RNG ported from `urandom.py` (`setSeed` → linear congruential).

## Phase 0 — Core port: parameters, RNG, resource parsers

**Goal:** clean Python 3 modules that read all PlantStudio resources; verify
parsing against the source data on disk.

### Tasks

1. Create `blender_addon/` package skeleton:
   ```
   blender_addon/
     __init__.py            # Blender addon registration (enabled in later phases)
     core/                  # Pure Python 3, NO Blender imports (pytest-testable)
       rng.py               # PdRandom port: setSeed, zeroToOne, randomPercent, randomNormalWithStdDev
       params.py            # Parameter containers mirroring pGeneral/pMeristem/pInternode/pLeaf/pInflorescence/pFruit/pTDO
       pla_parser.py        # Parse .pla files → params objects (incl. embedded TDOs)
       tdo_parser.py        # Parse .tdo files → {name, points, triangles}
       plant_library.py     # Species catalog: load *.pla dirs, list species, get species params
     tests/                 # pytest suite (pure core, no Blender needed)
   ```
2. Port `PdRandom` (`urandom.py`) exactly: `setSeed`, `initialize`,
   `randomNormalWithStdDev` (sum-of-12), `zeroToOne`, `randomPercent`,
   `randomSmallintSeedFromTime`. Deterministic given seed.
3. Port `PdStreamableObject` read conventions from `ufiler.py` to parse the
   `[name] start PlantStudio plant <v2.0>` sections and
   `ParameterName [kParameterKey] =value` lines. Handle the `start 3D object /
   end 3D object` embedded blocks (points/triangles).
4. Port the S-curve growth math from `umath.py` (linearGrowth,
   growthSCurve — params `0.05 0.05 0.95 0.95` style).
5. Load all 9 `.pla` files + `3D object library.tdo` from the repo's
   `examples/PlantStudio-master/for-olpc-python/`; assert 63 species + 57 TDOs.

## Phase 1 — Simulation core: plant, meristems, parts

**Goal:** faithful port of the growth engine — `Plant.nextDay()` builds the
phytomer tree exactly like PlantStudio.

### Tasks

1. Port `PdPlantPart` hierarchy (`upart.py`): `PdPlantPart` →
   `PdPhytomer`, `PdMeristem`, `PdInternode`, `PdLeaf`, `PdInflorescence`,
   `PdFlowerFruit`, `Pd3DObject`.
   - `partType()`, `partID`, `phytomerAttachedTo`, `isActive`, `isApical`,
     `isReproductive`, `gender`, live/dead biomass fields, `hasFallenOff`.
2. Port `PdMeristem.nextDay()` (`umerist.py`):
   - active meristems: `accumulateOrCreatePhytomer()` / inflorescence
   - inactive axillary: `contemplateBranching()` (branchingIndex,
     branchingDistance, apical dominance, secondary-branching flag)
   - `determinateProbability` → reproductive conversion when flowering starts
3. Port `PdPhytomer` creation: internode + leaf (+ opposite leaf if
   dicot/opposite arrangement), phyllotactic rotation angle, bud placement.
4. Port biomass distribution in `uplant.py` (`nextDay`: total biomass →
     growth-curve fraction → allocation to active parts by demand,
     `optimalFinalBiomass`, min/max days, stunting/recovery rules).
5. Port `PdInternode` growth: `linearGrowthWithFactor`, curving index,
   length/width from biomass (`kInternodeLengthAtOptimalFinalBiomass...`),
   bolting.
6. Port `PdLeaf` growth: area/draw-size from biomass, `leafWidth/LeafLength`
   params, simple-leaves-only flag.
7. Port `PdInflorescence` + `PdFlowerFruit` creation & growth
   (numApical/Axillary inflorescences, flowering start age,
   reproductive allocation fraction).
8. Age loop: `Plant.growTo(day)` = create plant → `nextDay()` × day.
   **Deterministic**: RNG seeded from species params at creation.

### Files touched
- `blender_addon/core/plant_part.py` (new — hierarchy)
- `blender_addon/core/meristem.py` (new)
- `blender_addon/core/phytomer.py` (new)
- `blender_addon/core/internode.py` (new)

## Phase 2 — Mesh output: turtle + polygon buffer

**Goal:** port the 3D turtle and convert part drawing into mesh geometry
(vertices + faces), replacing the file-export drawing surfaces.

### Tasks

1. Port `KfMatrix` + `KfPoint3D` (`u3dsupport.py`): position + rotation
   matrices, `move`, `rotateX/Y/Z` (256-degree turtle units as in source).
2. Port `KfTurtle` (`uturtle.py`) core: matrix stack (push/pop), `xyz`,
   `setScale`, line color. **Replace** `drawingSurface` with a
   `MeshBuffer` that accumulates:
   - polygons → triangles (faces), from `drawPolygon`
   - stem segments → tapered cylinder geometry (`drawStemSegment`:
     length, width, taperIndex, lineDivisions — port from u3dexport OBJ path)
   - TDOs → transformed point/triangle meshes (`draw3DObject`)
3. Port `PdTraverser` (`utravers.py`) minimal: traverse part tree with
   `kActivityDraw`, applying rotations/translations per part (phyllotactic
   rotation, branching angles, curving).
4. Port part `draw*` methods (`upart.py`, `u3dexport.py` conventions):
   colors per part (`kInternodeFaceColor`, `kLeafFaceColor`, front/back face
   colors), taper, amendments (scale multipliers).
5. Output: `MeshBuffer.to_mesh_data()` → `{vertices: [(x,y,z)...],
   faces: [[i,j,k]...], materials: [{name, color}...]}`.

### Files touched
- `blender_addon/core/matrix3d.py` (new — KfMatrix/KfPoint3D port)
- `blender_addon/core/turtle.py` (new — KfTurtle port)
- `blender_addon/core/mesh_buffer.py` (new)
- `blender_addon/core/traverser.py` (new)
- `blender_addon/core/draw.py` (new — part draw methods)
- `blender_addon/tests/test_mesh_output.py` (new)

### Definition of done
- [ ] A grown plant produces vertices+faces with expected part counts
- [ ] Stem cylinders have correct taper & divisions; leaves/TDOs transform correctly
- [ ] Colors preserved per part (front/backface)
- [ ] Determinism: same seed → identical mesh data
- [ ] Mesh output validated visually (dump to OBJ for a spot check)

## Phase 3 — Blender addon shell

**Goal:** the addon registers in Blender; plants appear as real mesh objects.

### Tasks

1. `blender_addon/__init__.py`: `bl_info`, register/unregister,
   import core (pure Python, no bpy in core).
2. UI panel (`N-panel`, e.g. `PT_PlantStudioPanel` in VIEW3D):
   - Species library loader (path to `for-olpc-python/`, or bundled copy)
   - Species dropdown (63 species), seed field, age (days) field
   - **"Add Plant"** operator: creates a new Blender object per plant
     (mesh from Phase 2), stored in collection `PlantStudio_Plants`,
     name `{species}_{seed}_{day}`
3. Operators:
   - `Add Plant`, `Step Day` (advance one plant +1 day and rebuild mesh),
   - `Grow To Age` (rebuild at target day), `Delete Plant`
4. Per-plant data: custom properties on the object (species, seed, day,
   params hash) so re-running "Grow To Age" reproduces deterministically.
5. Object naming + origin at ground; plant built Y-up.

## Phase 4 — Garden composition + GLB export into the pipeline

**Goal:** multiple plants in one scene, exported to the existing repo path.

### Tasks

1. Garden collection: `PlantStudio_Gardens/{garden_slug}/` with plant objects
   (Position/Rotation/Scale are Blender-native — free placement).
2. **"Export Garden GLB"** operator:
   - exports the selected garden collection via Blender's glTF 2.0 exporter
     (`bpy.ops.export_scene.gltf` with `export_format='GLB'`, apply transforms,
     preserve materials from part colors)
   - writes to `digital-garden-AR/src/assets/gardens/{garden-slug}.glb`
     (repo-relative, or user-chosen path)
   - supports per-plant overrides? No — PlantStudio params are per-species;
     per-plant variation comes from seed + day (existing config contract stays)
3. Optional: "Export growth-config.json" — writes the garden's plant list
   (species, seed, day → planted_date, position) to `growth-config.json`,
   matching the schema the AR pipeline expects.
4. Materials: create Blender materials from PlantStudio colors (roughness
   ~0.6, base color from faceColor), so GLB exports with colors.

## Phase 5 — Growth animation & polish

**Goal:** PlantStudio's signature feature — watch plants grow day by day.

### Tasks

1. **"Animate Growth"** operator: steps `nextDay()` per frame (or per N days),
   rebuilding meshes via a modal operator or frame-change handler.
   Options: days-per-frame, start/end day, auto-restart.
2. Timeline integration: store plant day in custom property; animate from 0
   to age-at-maturity using the plant's `kGeneralAgeAtMaturity`.
3. Performance: for animation, cache part tree and only rebuild mesh when
   day changes; consider `simpleLeavesOnly`/`straightLinesOnly` draw options
   (source has these — port them as quality/speed toggles).
4. UI polish: species preview (thumbnail via offscreen render or fast
   low-poly draw), randomize seed button, per-plant "Grow to maturity".

## Risks

| Risk | Mitigation |
|------|------------|
| PlantStudio source is Python 2 + Delphi wrappers — port is significant | Port in layers; core is pure-Python 3 & testable; source is reference, not copied |
| Biomass simulation complexity (thresholds, stunting, allocation) | Port `nextDay()` faithfully first, then tune; unit-test each rule against source behavior |
| Blender version API differences (4.x) | Target Blender 4.x LTS; isolate bpy usage in `operators.py`/`export_glb.py` |
| GLB material fidelity (PlantStudio colors → PBR) | Map faceColor to base_color, roughness 0.6; verify re-import |
| Determinism across runs/platforms | Ported RNG is pure arithmetic (no `time`/hash); test byte-identical part trees |
| .pla parsing quirks (embedded TDOs, comments, variants) | Test against all 9 libraries; parse leniently, fail loudly |

## Non-goals (this iteration)

- No GUI port of PlantStudio forms (breeder, wizard, animation files)
- No Genetics/breading features (out of scope; architecture leaves room later)
- Geometry Nodes are NOT used for simulation (display-only possible later)
- No changes to the existing grow/publish/deploy pipeline
